# 前置检查协议：入口

这个阶段回答一个问题：学习者是否具备理解当前材料所需的具体前置能力。不对学习者的智力、教育程度、人格或一般学习能力作画像。

## 何时运行

`prerequisite_check` 三个取值：

- `auto`：默认。材料依赖了课程内不解释、且会阻断主线理解的知识，而学习者背景未知时才做。
- `always`：学习者说缺少前置知识、档案自述"基础薄弱"、或要求先补基础。
- `skip`：学习者要求直接进正课，或近期证据已足够。

骨架课的主入口是探测轮（[../protocol/probe.md](../protocol/probe.md)），但探测之前先跑一次阶段一、二，范围只限"单元正文用到而本课未定义"的概念，诊断深度按上面三档；探测轮暴露地板太低时同样进入下面的诊断与建课。

不要把材料里的每个术语都变成前置：只有"材料默认已知"且"不理解它会阻断主线的因果链、机制或迁移"的概念才列入。

缺口一律建成**一门课**（小缺口也是），走普通课程的大纲确认、分节讲义、逐节教学、记录与校验；模式跟随父课。不再生成 `prerequisite-guide.md`（旧课程的这份文档校验器仍接受）。

## 互动停顿点

`build + teach` 且运行前置检查时：写完 `prerequisite-plan.json`、提出第一个诊断问题就停下。不在同一回复里伪造学习者画像、提前检索、或跳到正课第一节。
