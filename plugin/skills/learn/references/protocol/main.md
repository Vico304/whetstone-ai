# MAIN：主问题与把握标注

提出主问题前，先按 [deepen.md](deepen.md) 的话术询问是否细化本节。

## 主问题设计

优先要求学习者完成下列高价值行为中的两到三项：

- 用自己的话解释概念或机制；
- 说明为什么前一步方案不足；
- 描述关键输入如何变成输出；
- 指出两个概念的关系、方向和理由；
- 给出例子、反例或失败条件；
- 预测移除某个组件会发生什么。

结构讲解节与过程讲解节的主问题**原样取 `checkpoint.prompt`**（它已经写成"合上文档走一条路径"的形式），提问时请学习者先合上讲义与图——这两类文档学习期间随时可回查，验收时合上。避免只问"你理解了吗"、孤立术语定义、判断题和可从标题直接抄出的答案。要求学习者用自己的话说明"是什么、为什么需要、如何工作、与前后步骤什么关系"；按小节内容选择最相关的部分，不要求固定措辞。

## 把握标注

主问题作答前，请学习者顺带说一句把握：**有把握 / 没把握 / 不知道**（一句话即可，不打断作答）。用途：

- 记录为 `--confidence 5 / 3 / 1`（`learning_state.py record` 或 `lrg_record.py append`）；
- 反馈时优先处理**有把握且错误**的内容——这是最有价值的诊断信号，应明确指出"这里你很确定，但材料的说法不同"并给出证据定位；
- "没把握"是校准信号：答对答错都值得一句说明偏在哪；"不知道"但答对的明确肯定；
- 把握只是诊断信号，不是掌握证明，不参与 verdict 判定。

学习者不愿标注时不坚持，记录为空即可。

提出主问题后进入 AWAITING_ATTEMPT，把对话交还学习者。

## supporting 概念的验收（学习者主动要求时）

学习者说"验收 X"且 X 是本节（或已完成 unit）的 `supporting` 概念时：从 lesson-plan 该概念的 `check` 取 `prompt` 出题（不展示 criteria），等待作答，按 [assess.md](assess.md) 评估，用 `check.criteria` 判 `criteria_met`，记录为 `lrg_record.py append --kind supporting --concept <id>`（不加 `--progress`，不影响本节 verdict）。反馈按 [feedback.md](feedback.md) 但最多一层追问。学习者不要求时不出。
