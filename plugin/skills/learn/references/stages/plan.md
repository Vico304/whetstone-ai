# 阶段 3：学习计划 → `learning-plan.md`（逐门确认）

把阶段 2 的定级与切分结果排成课程序列，**每门课单独确认**，写入工作区根目录的 `learning-plan.md`。

## 生成

按 [../../assets/learning-plan-template.md](../../assets/learning-plan-template.md)：每门课给出名称、材料子集（具体路径）、目标一句话、规模估计（KB 或行数 → 预计 unit 数）、模式建议、前置依赖、可复制的 `learn` 调用语句。附排除项及理由、风险提示。

## 取向为 domain 时的计划形状

计划分两段：**第一段是骨架课**（一门，或按依赖拆成 `skeleton-1 → skeleton-2 …`），材料列的是证据池与保留项；**第二段是分支候选**，每条对应材料里的一个子系统/模块，标注它体现的原理与实际工作关系，状态一律"待骨架课结束后选择"——现在不确认、不排序、不生成大纲。逐门确认只对骨架课做。分支课在骨架课 finish 时由学习者选定后追加为普通课程（`shape: branch`，`parent_course` 指向骨架课）。

## 逐门确认

1. 先用一张表列出全部候选课程（名称、材料、规模、顺序），让学习者看到全貌；
2. 然后**一门一条消息**确认："课程 1《…》——材料 …、目标 …、预计 … 个 unit。接受 / 修改 / 删掉？"学习者可随时说"后面的都接受"结束逐门确认；
3. 候选 ≤ 3 门时，允许在一条消息里一起确认；
4. 学习者的修改直接写回；被删的课程移到"暂不学"并保留理由；
5. 确认完，标出**第一门课**并给出它的调用语句。

## 不做

- 不在这一阶段生成任何课程的大纲——大纲在该课开始时才做（阶段 4）；
- 不把 C 级（生成中间物）材料列进任何课程的来源；
- 不替学习者删课程；只建议。

完成后：learn 流程继续进入第一门课的阶段 4；guide 调用则在此结束，报告计划路径。
