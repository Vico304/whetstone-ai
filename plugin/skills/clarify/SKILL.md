# Clarify：按节的概念解释

学习者在课程目录的任何文档里用 `[[概念名]]` 标记不理解的概念，或把概念列进 `concepts/_inbox.md`，然后调用本技能。技能把待处理的概念按它们所属的节归组，**一节一份文档** `concepts/<节 id>.md`：一节里只有一个概念不懂，只解释这个概念；两个以上，说明这一节的基础不牢，逐条解释之后再从这些概念出发把这一节针对性地重讲一遍。文档的 `aliases` 列出它解释的全部概念，讲义里的 `[[概念名]]` 因此仍能解析到它。

调用方式：Codex 中 `$clarify`；Claude Code 中 `/whetstone:clarify` 或自然语言触发；DeepSeek Harness 中 `/clarify`；pi 中 `/skill:clarify`。

## 路径解析约定

本文档中 `scripts/`、`assets/` 相对于本 SKILL.md 所在目录（技能目录）解析：

- Claude Code（插件安装）：技能目录为 `${CLAUDE_PLUGIN_ROOT}/skills/clarify`；
- Claude Code 以个人/项目技能安装（`~/.claude/skills/clarify/`）：技能目录为 `${CLAUDE_SKILL_DIR}`；
- DeepSeek Harness / 直接放入 `~/.agents/skills/` 的环境：技能目录即被安装的 skill 目录本身；
- pi：系统提示里 `<location>` 给出本 SKILL.md 的绝对路径，技能目录就是它所在的目录。

shell 的 cwd 通常是用户项目目录，不要以相对路径直接执行脚本。文档写入课程目录的 `concepts/`，与技能目录无关。

## 输入来源

按优先级合并三类输入，去重后逐个处理：

1. 用户在调用时直接给出的概念名；
2. `concepts/_inbox.md` 中的条目（每行一个，允许 `- 概念` 列表格式或裸文本）；
3. **当前课程目录**内所有 `.md` 文件中**未解决的 wikilink**（`[[目标]]` 没有对应笔记文件）。

范围只是当前这一门课：调用时指定了课程目录就是它；只给了工作区或计划目录时，脚本取最近更新过进度的那门课，其他课程只报告 inbox 里的待处理数，不扫描、不处理——学习者点名（`--course <目录>`）或说"全部"（`--all`）时才扩大。用脚本做确定性扫描，不要凭印象判断哪些链接未解决：

```bash
python3 <技能目录>/scripts/scan_wikilinks.py <课程目录或工作区>            # 默认只扫当前课程
python3 <技能目录>/scripts/scan_wikilinks.py <工作区> --course <课程目录>   # 指定一门
python3 <技能目录>/scripts/scan_wikilinks.py <工作区> --all                # 全部课程
```

脚本按文件名和 frontmatter `aliases`（行内 `[a, b]` 或 YAML 块列表均可）匹配已有文档（课程里其他 `.md` 的文件名也算已解析），输出缺失目标及其出现位置，并按节归组：`by_unit[]` 每项给出节 id、概念清单、`scope`（一个概念 `isolated`，两个以上 `cluster`）和该写的文件名。归组依据：概念被标记在哪份 `units/<id>.md`，否则课程数据里哪一节列了它，否则哪份讲义提到它；都没有的归为“未归属”。围栏代码块与行内代码中的 `[[...]]` 会被跳过；HTML 注释等其他嵌入形式仍可能误报，处理前人工确认。

## 工作流

1. 定位当前课程目录（含 `lesson-plan.json` 或 `teaching-guide.md`；给工作区时由脚本按最近的进度更新选出）；没有课程时也可以在用户指定的任意笔记目录内工作，但来源约束仍然生效。
2. 运行扫描脚本，按 `by_unit` 向用户报告：每节标了哪些概念、判为 `isolated` 还是 `cluster`；用一句话带过其他课程的待处理数。一次处理不超过 3 节，其余留在 inbox。
3. 对每一节，写或更新 `concepts/<节 id>.md`（模板 [assets/unit-note-template.md](assets/unit-note-template.md)）：
   - 先在课程的来源材料（`sources.json` 所列文件、`lesson-plan.json` 的 `source_refs`）里检索每个概念的出现位置；材料内有依据的按实际支持类型标注（`explicit / entailed`），材料未覆盖、需要外部检索时遵循外部存档规则：可审核来源、标记 `external`、记录出处，检索不可用时明确说明而不伪造；
   - `isolated`：只写这一个概念的四行（是什么、在本节机制里的位置、一个材料语境的例子、来源），不写“深化”一节，不扩展到相邻概念；
   - `cluster`：每个概念各四行，然后写“针对这一节的深化”：从这些概念出发重讲本节机制、一个换情境的例子、边界与易混处、与前后节的关系；
   - 文档开头一句写明判断依据（几个概念、为什么孤立或成簇），供学习者核对；`aliases` 列出全部概念；已有文档时追加新概念、不覆盖学习者手写的部分；同名的旧单概念文件保留。
4. 处理完毕后从 `_inbox.md` 移除已完成条目（inbox 是队列，不是记录），并报告：新建或更新了哪几节的文档、哪些概念在材料中找不到依据、哪些留待下次。

## 文档契约

每份按节的文档必须有（模板已体现）：开头的判断一句与**先试提示**（读每条之前先用自己的话说一遍）；每个概念四行——是什么、在本节机制里的位置、一个贴近材料的例子、来源（path、locator、support 类型）；`cluster` 时多一节“针对这一节的深化”，含一个换情境的例子与边界；出现位置链接回该节（`[[<节 id>]]`）。frontmatter：`unit`、`aliases`（全部概念，含中英文变体）、`scope`、`status`（`draft | grounded | external-supplemented`）。

## 边界

- **不得泄漏检查点**：若概念是某个尚未作答节的核心概念，文档照常生成（阅读是学习的一部分），但“深化”一节不得逐字给出该节 `checkpoint.criteria` 的答案，且先试提示改为更明确的"建议先完成该节重建再阅读本条"；
- 默认**不改写讲义**：文档单向链接回讲义即可；用户明确要求时才在讲义的概念首次出现处加 `[[链接]]`，且不得改变原文含义；
- 不把概念解释当摘要器出口：一次为整门课所有概念写解释不是本技能的用途，文档只为学习者实际标记的疑问服务；`cluster` 的深化也只从被标记的概念出发，不重写整节讲义；
- Obsidian 互链依赖文件名或别名匹配：建议用户把课程目录放进 vault（或作为 vault 打开）；概念改名时同步更新 `aliases` 与引用。
