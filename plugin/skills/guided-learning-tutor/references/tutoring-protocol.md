# 逐节教学协议

## 状态机

```text
READY
  ↓ 只揭示本节“当前问题”，请学习者预测方案
PREDICT
  ↓ 学习者预测后，揭示方案与机制，对照预测简评一句
MAIN ←──────────────────┐
  ↓ 提出主问题前询问是否细化本节        │
  ├─ 学习者选择细化 → DEEPEN（生成细化文档，读完返回）
  ↓ 请学习者先自评信心（1–5）再作答
AWAITING_ATTEMPT
  ↓ 学习者回答
ASSESS
  ├─ MASTERED ───────→ 简短巩固后进入下一节 READY
  ├─ PARTIAL ────────→ 一个针对性追问 → AWAITING_RETRY
  ├─ MISCONCEPTION ──→ 证据纠正 + AWAITING_RETRY
  ├─ SKIPPED ────────→ 下一节 READY
  └─ PAUSED ─────────→ 保存当前位置
```

一次回复只推进一个状态。提出问题或追问后应把对话交还给学习者，不同时回答自己的问题。

若正课中暴露出之前未识别的前置缺口，只对受影响的概念簇运行 [prerequisite-protocol.md](prerequisite-protocol.md)，补充和桥接复测后回到原小节。不因一个缺口将整门课程或学习者状态清零。

## 分段揭示（PREDICT）

不要让学习者先读完整节讲义再答题。按 lesson-plan 字段分阶段揭示：

1. READY 时只呈现 `problem`，问“你觉得应该怎么解决？”或“你预计难点在哪里？”；
2. 收到预测后再呈现 `solution` 与 `mechanism`，用一两句对照学习者预测与材料实际方案的异同；预测只为激活思考，不判分、不记录 verdict；
3. `tradeoffs` 与 `new_problem` 留作主问题和追问的素材，不必预先展示。

以下情况跳过 PREDICT 直接进入 MAIN：学习者明确已读过本节材料；小节过短没有预测空间；学习者要求加快节奏。跳过是正常路径。

## 按需细化（DEEPEN）

teaching-guide 是宏观框架，不是全部深度。每节呈现 `solution` 与 `mechanism` 后、提出主问题前，明确告知学习者可以选择先细化本节：

> “这一节内部还有 {概念 A、概念 B} 等衍生概念。想先深入哪一个，还是直接回答本节问题？”

学习者选择细化时：

1. 生成 `zoom/<section-id>-guide.md`（契约见 lesson-contract）：只覆盖本节内部的衍生概念与机制，比主讲义更详细、例子更多（每个概念至少两个例子，其中一个贴近材料语境，一个换情境）；涉及的概念用 `[[概念名]]` 链接，需要独立成篇的概念交给 clarify 技能生成概念笔记；
2. 细化文档同样受来源约束：材料内依据标 `explicit / entailed`，材料外补充标 `external` 并附出处；
3. 学习者读完细化文档后，**回到本节主问题作答**——细化是主问题的准备，不替代主问题。细化后的作答仍按原 criteria 评估，verdict 照常记录；
4. 一节最多细化一次；学习者在细化后仍答不出时走正常的追问和提示路径，不再生成第二层细化文档。

细化由学习者按需触发，不默认展开。判断信号：学习者主动要求；PREDICT 阶段的预测显示对本节前置概念完全没有方向；或上一节 checkpoint 暴露了与本节强相关的概念缺口。禁止在 build 阶段预生成所有小节的细化文档——按需生成是控制框架规模的手段，预生成会把它变回"框架过大"。

## 信心标注

主问题作答前，请学习者顺带自评信心（1–5，一句话即可，不打断作答）。用途：

- 通过 `learning_state.py record --confidence` 记录；
- 反馈时优先处理**高信心且错误**的内容——这是最有价值的诊断信号，应明确指出“这里你很确定，但材料的说法不同”并给出证据定位；
- 低信心但正确的回答应明确肯定，帮助校准；
- 信心只是诊断信号，不是掌握证明，不参与 verdict 判定。

学习者不愿标注时不坚持，记录为空即可。

## 主问题设计

优先要求学习者完成下列高价值行为中的两到三项：

- 用自己的话解释概念或机制；
- 说明为什么前一步方案不足；
- 描述关键输入如何变成输出；
- 指出两个概念的关系、方向和理由；
- 给出例子、反例或失败条件；
- 预测移除某个组件会发生什么。

避免只问“你理解了吗”、孤立术语定义、判断题和可从标题直接抄出的答案。

## 针对性追问

评估为 `partial` 或出现高信心误解时，不直接给完整解释，而是针对回答中**实际暴露的最弱一点**，从下表选择一种追问（一次只问一个）：

| 类型 | 形式 |
|---|---|
| 边界 | “你说 X 做了 A，什么情况下 X 会失效？” |
| 反例 | “如果出现〔反例场景〕，你的解释还成立吗？” |
| 因果深挖 | “你说 A 导致 B，中间发生了什么？” |
| 删除思想实验 | “把 X 拿掉，哪里最先出问题？” |
| 对比 | “X 和 Y 都能做到这一点，材料为什么选 X？” |

追问必须由本次回答内容驱动，不得照抄题库。同一小节追问最多两层；两层后仍未解释清楚，给完整解释并要求学习者用新表述总结，然后继续。

## 同节不重复出题

同一小节内不用相似问题再次验证。需要再验证时：

- 当场改用**更高认知层级**的问题（刚解释完机制，就要求预测或应用），层级爬升本身即是验证；
- 或留给下次 `resume` 开场的变式检索（见下节）。即时重复答对提供的掌握证据很弱，还制造重复感。

## resume 开场：变式检索

进入 `resume` 时，先不进入未完成小节。开场从**已完成的小节**中选一个概念，出一道变式问题：换情境或换角度，但考察同一深层机制；禁止复用原 checkpoint 措辞。学习者作答并获得简短反馈后，再用一两句话重建上下文（“当前主线走到哪、上次遗留什么问题”），然后进入未完成小节的 READY。

变式题的作答通过 `record` 追加到对应已完成小节，verdict 照常判定；`mastered` 的小节因变式失败可回到 `in_progress`，这是正常的遗忘信号，不是倒退。

## 评估

使用 `lesson-plan.json` 的 `criteria` 评估含义，不要求关键词或固定表述完全一致。分别判断：

- 核心问题是否识别；
- 机制是否因果连贯；
- 前后步骤关系是否正确；
- 边界或代价是否理解；
- 是否出现高信心误解；
- 回答中的新增联系是否有合理依据。

结果采用以下状态：

| 状态 | 含义 | 下一步 |
|---|---|---|
| `mastered` | 核心概念与关系已解释清楚 | 简短巩固后进入下一节 |
| `partial` | 主线正确但缺一项重要机制或关系 | 指出已对部分，给一个针对性追问 |
| `retry` | 存在会影响后续理解的误解 | 指向证据或给最小纠正，再答一次 |
| `skipped` | 用户明确不作答或要跳过 | 记录跳过，必要时给极短摘要 |

## 反馈顺序

1. 用一两句指出回答中确实正确的具体内容；
2. 优先指出高信心误解，其次是最重要的遗漏；一次只处理一个问题，不堆叠；
3. 给一个最小提示、反例或证据定位，或按追问表提出一个针对性追问；
4. 第二次仍无法解释时，再给完整解释并要求学习者用新的表述总结。

如果怀疑课程参考本身有错，暂停判分并回到来源。把结果标记为材料/机器参考不确定，而不是自动判学习者错误。

## 进度记录

文件模式使用：

```bash
python3 scripts/learning_state.py init \
  --lesson-plan path/to/lesson-plan.json \
  --output path/to/learning-progress.json

python3 scripts/learning_state.py record \
  --state path/to/learning-progress.json \
  --section-id s01 \
  --response-file path/to/raw-response.txt \
  --feedback-file path/to/feedback.txt \
  --verdict partial \
  --confidence 4
```

`record` 会追加尝试并原子更新状态；它不会删除早期回答。学习者标注了信心就传 `--confidence`，未标注则省略。若不适合把回答写入文件，则只在当前对话保留，并明确无法跨 session 恢复。

## 课程结束

最后不要逐节重复答案。要求学习者：

1. 不看小节顺序，重述总体问题链；
2. 选择一个组件，解释删除或替换它的后果；
3. 在新案例中应用同一机制；
4. 标出仍不确定的关系。

最终总结应区分“已经解释成功”“提示后成功”“仍待复习”“材料本身不确定”。注意：本课程内的成功多为即时或短延迟证据；对“已稳定理解”的表述应保留这一限定，真正的稳定证据来自之后 `resume` 的变式检索表现。
