# whetstone核心共识：为什么深度学习系统需要证据、双轨重建与差异诊断

## 如何学习这份文档

这不是原文的逐章摘要，而是一条设计问题链。每节先提出前一步尚未解决的问题，再说明新机制为什么出现、如何工作、有什么代价。读完一节后，请合上该节，用自己的话回答“轮到你解释”。

原交接文档中的 Agent 命令、权限说明和流程要求在这里都作为分析材料处理，并没有被当作本次任务的新指令执行。

## 学习目标与材料范围

完成后，你应该能够：

- 解释项目为什么不等于“AI 摘要器”；
- 从真实问题出发，依次解释 SEL、MRG 和 LRG 为何需要分开；
- 说明双图发生冲突时为什么要回到证据，而不是默认机器或学习者正确；
- 解释提示渐隐、延迟重建、局部学习子图和多维学习者状态的实际意义；
- 判断哪些设计适合自动化，哪些必须保留不确定或上报用户。

本课程覆盖交接文档的核心共识与学习闭环。它不会展开所有对象字段、关系注册表实现或材料解析技术选型；这些细节可在掌握主线后继续学习。

## 总体问题

项目面对的根本困难是：材料通常按线性顺序呈现，学习时间又可能碎片化。学习者可以读完很多内容，却未必能在没有原文时回忆概念、解释机制、重建关系或用于新问题。普通 LLM 虽然能给出流畅答案，但没有来源约束时，错误也可能被长期记成“学会了的知识”。

所以目标不是更快读完，也不是生成更多知识卡片，而是让学习者逐步形成有证据、可解释、可调用、可迁移的心智模型。

## 宏观系统地图

```text
原始材料
   │
   ▼
原文证据层 SEL ───────────────┐
“材料在什么位置说了什么”       │
   │                           │
   ▼                           │
机器参考图 MRG                 │
“机器怎样组织有来源的概念与关系” │
   │                           │
   ├──── 隐藏完整参考 ────┐     │
   │                      ▼     │
   │               学习者重建图 LRG
   │               “此刻我能解释什么”
   │                      │
   └──────────┬───────────┘
              ▼
     概念 / 命题 / 关系差异
              │
              ▼
     回到 SEL 裁决与针对性反馈
              │
              ▼
       修订、延迟重建与迁移
              │
              ▼
      更新多维学习者状态并选下一活动
```

## 问题链预览

1. “看过”不等于形成可调用的理解，因此要让学习者主动重建。
2. 要诊断重建，就需要参考；但无来源的机器答案可能把错误变成伪知识，因此先建立证据层。
3. 证据仍然是线性的，因此需要机器参考图组织概念、命题和关系。
4. 完整参考会泄露答案，因此另建学习者重建图保存无提示下的真实理解。
5. 两张图都可能错，因此差异必须拆到概念、命题和关系，再回到证据裁决。
6. 一次即时回答会高估掌握，因此要提示渐隐、延迟重建和新情境迁移。
7. 完整图谱会造成认知负担，因此每次只选择动态局部学习单元，同时周期性整合。
8. 自动化可能优化错目标，因此用范围、上报与学习效果指标约束系统演化。

## 1. 先定义真正的问题：从“看过”到“可调用”

### 当前问题

阅读页数、章节完成和“这句话我好像见过”都很容易测量，却不能证明学习者能在需要时调用知识。看到概念名后能复述，也可能只是识别线索触发的短期记忆。

### 解决方案

把学习成果改写为可观察行为：学习者要能在更少提示下，用自己的语言解释概念，指出关系的类型和方向，说明为什么存在这条关系，并在新案例里应用它。

### 工作机制

主动解释迫使学习者重新生成命题；关系重建迫使他组织结构；反例和迁移迫使他识别适用边界。原文遮住的遗漏、误解和碎片关系由此外显。

### 实际意义

这一步决定了项目的优化目标。如果目标仍是“看完多少”，后面的图谱和 AI 只会加速内容消费；只有把学习者能做什么当作结果，系统才会围绕真正理解设计。

### 局限与代价

- 主动重建更费力，短期体验不如浏览轻松；
- 开放解释比选择题难评估；
- 初学者仍需要概念名或锚点作为脚手架。

### 它引出的新问题

要判断学习者的解释缺了什么，系统需要一个参考结构。但如果参考只是 LLM 的流畅总结，它自己可能错，也可能无法说明依据。

### 关键概念

- **可调用的心智模型**：没有原文摆在面前时，仍能回忆、解释关系并用于新问题。
- **主动重建**：由学习者重新生成概念和结构，而不是识别或抄写现成答案。
- **迁移**：把材料中的机制用于未直接展示的新情境。

### 来源

- `## 2. 项目要解决的问题`（`explicit`）：明确区分阅读完成与可调用、可迁移的心智模型。
- `## 3. 已确认的顶层共识 / 3.1–3.2`（`explicit`）：否定摘要器定位，并把主动重建设为核心行为。

### 轮到你解释

为什么“看完了”和“看到概念名后会复述”都不能证明已经形成可调用的心智模型？主动重建会多暴露哪两类信息？

## 2. 为何先保存证据：防止流畅答案变成伪知识

### 当前问题

系统需要参考学习者的回答，但材料版本和解析结果会变化。只保存摘要会丢失作者原来的限定条件；只保存页码又会因版本、排版改变而失效。扫描、错序或漏列还可能让机器在错误文本上推理。

### 解决方案

建立原文证据层 SEL。它保存文档版本、不可变 SourceUnit、稳定定位、上下文、解析程序信息和内容校验值。解析修正产生新版本，而不是无痕改写已经冻结的来源。

### 工作机制

后续 Concept、Claim 和 Relation 都指回具体 SourceUnit。发生争议时，系统可以重新取回原文上下文，并判断问题来自解析、机器理解、学习者解释，还是原文本身含糊。

### 实际意义

SEL 提供了机器参考和学习者重建之外的第三个裁决基础。它让“这是谁说的、在哪个版本、什么上下文”成为知识的一部分，而不是事后补引用。

### 局限与代价

- 版本、定位和校验值会增加数据管理成本；
- 复杂 PDF、公式、表格和图片仍可能解析失败；
- 原文有证据只说明作者这样表达，不证明观点客观正确。

### 它引出的新问题

证据能回答“材料说了什么”，却仍是一组线性单元；它不会自动告诉我们哪些概念构成机制，关系方向是什么，或者该怎样选择一个可学习的局部结构。

### 关键概念

- **SEL**：保存材料版本、来源单元和定位的证据裁决层。
- **SourceUnit**：段落、公式、表格、例子等最小稳定来源单元。
- **解析不确定性**：由读取与版面恢复失败造成的问题，不等同于知识语义不确定。

### 来源

- `## 4. 核心逻辑：证据层与双轨图谱 / 4.1`（`explicit`）：定义 SEL 及其不可变版本规则。
- `## 13. 材料解析的概念性原则`（`explicit`）：要求保留结构、定位和失败标记，并禁止自动补全未读内容。

### 轮到你解释

如果系统只保存一段 AI 摘要和页码，而不保存 SourceUnit、版本与定位，机器参考和学习者发生冲突时会出现什么问题？

## 3. 为何还要机器参考图：证据本身不会自动形成结构

### 当前问题

SEL 让内容可核查，但它没有自动把表达归一为概念，也没有把长段解释拆成可独立检查的 Claim，更没有说明两个概念是因果、组成、对比还是先修关系。

### 解决方案

建立 MRG：在来源约束下，用规范化 Concept、原子 Claim 和有类型、有方向的 Relation 组织材料。机器先生成候选，再进行确定性检查、证据验证、跨章节一致性检查，最后才发布新版本。

### 工作机制

职责分离防止一次流畅推理同时完成“生成、审核、改写和发布”。支持类型也与审核状态分开：一条结论可以是原文明示但尚未审核，也可以已审核却仍只是教学推断。

### 实际意义

MRG 把档案变成可导航的参考地图。系统才能选择局部学习子图、比较学习者关系，并在不同章节发现重复或冲突。

### 局限与代价

- 概念粒度和关系类型需要语义判断；
- 词频、共现和向量距离只能提供候选，不能证明关系；
- MRG 仍然是可修订参考，不是标准答案。

### 它引出的新问题

如果把这张完整地图直接展示给学习者，他可能只是在地图上描线。系统仍不知道他合上参考后能否自己画出结构。

### 关键概念

- **MRG**：有来源、可审核、可版本化的机器参考结构。
- **Claim**：可独立检查支持或反驳的原子命题。
- **支持类型**：区分明示、蕴含、教学推断、外部知识和无支持。

### 来源

- `## 4. 核心逻辑：证据层与双轨图谱 / 4.2`（`explicit`）：定义 MRG。
- `## 7. 机器知识管线与 Agent 权限`（`explicit`）：定义候选、验证和发布边界。
- `## 8. 支持类型和状态必须分开`（`explicit`）：防止用单一置信度混合不同判断。

### 轮到你解释

为什么有了 SEL 仍需要 MRG？同时，为什么 MRG 不能直接成为不可质疑的标准答案？

## 4. 为何另建学习者重建图：看到答案不等于会解释

### 当前问题

完整 MRG 会泄露概念和关系。学习者可以在强提示下复述或修改机器图，但这种表现无法证明他在缺少参考时真正掌握了什么。

### 解决方案

建立独立的 LRG，记录学习者在特定时间、延迟和提示条件下主动生成的概念解释、关系、理由、例子和不确定性。首次重建前隐藏完整参考。

### 工作机制

系统分别保存首次回答、反馈后的修订和延迟后的再次重建。LRG 不覆盖 MRG，修订也不覆盖首次尝试。个人扩展可以保留，但不能未经区分写成原材料观点。

### 实际意义

LRG 是学习证据，而不是便宜的知识库标注。它记录学习者实际外显的结构，让遗漏、错误信念、新增合理连接和信心校准都能被观察。

### 局限与代价

- 自由解释成本较高；
- 初学者需要恰当脚手架；
- 学习者的新观点与材料观点必须分开管理。

### 它引出的新问题

两张图分开后一定会出现差异，而机器和学习者都可能出错。简单比较整段文字，或默认机器答案正确，都不足以诊断。

### 关键概念

- **LRG**：特定时间和提示条件下，学习者能外显的理解结构。
- **LearnerAttempt**：带延迟、提示和参考可见性的一次重建。
- **不覆盖原则**：保留机器参考、首次回答和修订的逻辑边界与历史。

### 来源

- `## 4. 核心逻辑：证据层与双轨图谱 / 4.3–4.4`（`explicit`）：定义 LRG 与三层关系。
- `## 9. 学习闭环共识 / 9.1`（`explicit`）：规定隐藏参考、保存首次重建、比较和延迟再次重建。

### 轮到你解释

为什么不能让学习者直接在 MRG 上改“正确答案”？请从学习证据和数据版本两个角度解释。

## 5. 分歧如何变成诊断：两张图都不能直接当裁判

### 当前问题

机器和学习者可能只是使用了不同别名或粒度，也可能在命题、关系类型或方向上真正冲突。整段文本相似度无法区分这些情况。

### 解决方案

比较按四步进行：先做概念对齐，再拆原子命题，然后比较关系端点、类型、方向和理由，最后对实质冲突取回来源证据。

### 工作机制

向量相似度只负责召回候选，不负责判对错。差异可标记为一致、遗漏、部分覆盖、冲突、学习者新增合理联系、怀疑 MRG 错误、仅表示不同、原文模糊或尚无法解决。不同证据组合对应学习反馈、MRG 修订候选、多观点保留或用户上报。

### 实际意义

差异同时服务两件事：找出学习者的薄弱点，也找出机器参考的错误。系统不必把其中任何一方预设为权威。

### 局限与代价

- 概念粒度和命题拆分仍可能有偏差；
- Comparator 可能因先看到 MRG 而偏向机器；
- 高影响冲突需要人工裁决。

### 它引出的新问题

即使这一次差异分类正确，刚读完、强提示下的回答仍可能来自短期记忆，不能代表长期保持。

### 关键概念

- **ComparisonRecord**：记录一次 MRG/LRG 差异、证据和处理建议。
- **概念对齐**：同时检查别名、语义、粒度和上下文。
- **证据裁决**：发生实质冲突时回到 SourceUnit，而不是靠相似度决定。

### 来源

- `## 10. 双图比较与分歧处理`（`explicit`）：给出比较顺序、类别和裁决表。
- `## 14. 什么时候必须上报`（`explicit`）：定义单个 Agent 不能静默决定的冲突。

### 轮到你解释

学习者把一个概念拆成两个，而 MRG 合成一个时，为什么不能直接用语义相似度判错？你会按什么顺序处理？

## 6. 为什么要提示渐隐与延迟重建：即时表现会高估掌握

### 当前问题

刚阅读后在全部概念名提示下表现良好，可能只说明线索依赖和短期可用。一次回答也不能支持一个笼统的“掌握度”。

### 解决方案

逐步从全概念名过渡到少量锚点、无概念名主题和新情境迁移，并在延迟后重新解释和重建关系。学习者状态分开记录回忆、解释、关系、应用、迁移、信心和错误信念。

### 工作机制

每次尝试都记录延迟和提示条件。即时识别的证据较弱；延迟解释、延迟关系重建和新情境迁移依次提供更强证据。多次尝试共同修正状态，而不是让一次回答永久定性。

### 实际意义

系统能区分“刚看过会说”“一周后仍能解释”和“能用于新问题”。下一活动也可以针对关系薄弱、迁移失败或高信心错误，而不是重复整章。

### 局限与代价

- 延迟评估需要持久化和再次唤回；
- 提示减少过快或过慢都会失真；
- 多维状态真实但更难展示和调度。

### 它引出的新问题

重复测量和提示渐隐需要控制每次任务的规模。把完整机器图交给学习者会造成认知负担，过小的任务又会制造碎片。

### 关键概念

- **提示渐隐**：逐步减少概念和结构线索。
- **延迟重建**：隔一段时间重新生成理解，以检验保持。
- **学习者状态**：由多次行为推断的多维、可修正状态。

### 来源

- `## 9. 学习闭环共识 / 9.2`（`explicit`）：给出四阶段提示变化。
- `## 11. 学习者模型共识`（`explicit`）：定义多维状态和证据强度。

### 轮到你解释

一个学习者刚读完后能在全部概念名提示下解释，但一周后无提示时无法重建关系。系统应该如何描述他的状态，而不是简单说“掌握/未掌握”？

## 7. 如何控制一次学习的负担：完整图谱不等于有效活动

### 当前问题

机器可以维护完整章节图，但学习者一次重建全部内容会让繁琐维护吞噬学习。相反，只做孤立微题又无法形成跨概念结构。

### 解决方案

动态生成 LearningUnit：围绕一个中心概念、少量直接相关概念、一至两个关键关系和一个例子、反例或应用任务。系统还要周期性安排跨概念整合。

### 工作机制

活动选择综合学习目标、先修影响、过去错误、遗忘状态、参考不确定性、可用时间和最近上下文。中断恢复不是只回到页码，而是唤回“正在理解什么、已经掌握什么、上次的疑问是什么”。

### 实际意义

来源章节只是材料结构，LearningUnit 才是针对当前学习者的活动结构。它在认知负担和整体整合之间寻找可验证的平衡。

### 局限与代价

- 最佳概念和关系数量仍未知；
- 动态选择依赖可靠状态估计；
- 个性化路径需要保持可解释性。

### 它引出的新问题

系统一旦自动选择活动和维护图谱，很容易优化边数、完成率和自动化率，却忘了真正要改善的是延迟保持和迁移。

### 关键概念

- **LearningUnit**：根据目标、状态和时间动态组织的学习活动。
- **学习子图**：一次活动处理的最小连贯概念与关系集合。
- **中断恢复**：恢复问题和心智上下文，而不是阅读位置。

### 来源

- `## 9. 学习闭环共识 / 9.3`（`explicit`）：定义小型学习子图的建议形态。
- `## 12. 学习策略的方向性共识`（`explicit`）：定义活动选择和中断恢复。

### 轮到你解释

为什么一次只学一个孤立概念和一次重建完整章节都不是理想方案？一个合适的 LearningUnit 至少应包含什么？

## 8. 用边界与评估约束自动化：防止系统优化错目标

### 当前问题

更多抽取、更多连边、更高自动化和更漂亮的可视化都很显眼，却可能增加操作成本而没有改善学习。复杂系统还容易把尚未验证的研究假设写成既定真理。

### 解决方案

明确当前范围、默认不追求的能力、必须上报的高风险决定，以及三类成功标准：机器参考质量、学习效果、双轨机制的额外价值。

### 工作机制

核心概念拆分、关系 schema 改动、来源冲突和持续不确定性要形成含证据、候选解释和风险的审核包。产品评估要看延迟回忆、关系重建、迁移、错误修正、静默错误和维护时间，而不是只看系统产量。

### 实际意义

这些边界让技术继续服务于学习目标，也为未来是否增加 MCP、图数据库、多 Agent 或可视化提供可证伪依据。

### 局限与代价

- 延迟学习效果需要较长实验周期；
- 人工审核会降低自动化率；
- 不同学科可能需要不同粒度和关系类型。

### 最终边界

系统允许“不确定、原文模糊、多种解释、当前无证据”。保持诚实的不完整，比自动生成一张看似完整但错误的图更符合项目目标。

### 关键概念

- **上报**：把高影响、无法安全自动裁决的问题连同证据和风险交给用户。
- **双轨额外价值**：双图分离是否真正发现了机器错误和学习误解，并值得额外成本。
- **静默错误率**：没有被发现或上报、却进入稳定知识或反馈的错误比例。

### 来源

- `## 14. 什么时候必须上报`（`explicit`）：定义上报边界和审核包。
- `## 15. 成功标准和评估维度`（`explicit`）：定义三类指标。
- `## 16–17. 当前范围边界与尚未定论的研究问题`（`explicit`）：区分当前优先、默认不追求和未验证假设。

### 轮到你解释

如果一个版本让图谱边数翻倍、自动处理率达到 95%，但学习者的延迟关系重建没有改善，你会如何评价它？还需要看哪些指标？

## 整体重述与迁移挑战

现在不要按章节标题背诵。请从最初问题开始，说明为什么每一步都会逼出下一步：

```text
被动阅读不足
→ 需要主动重建
→ 需要可比较的参考
→ 参考必须先有来源证据
→ 证据还需组织成 MRG
→ MRG 不能覆盖真实学习，因此另建 LRG
→ 双图差异要回证据分类
→ 即时差异不足以证明保持，因此提示渐隐和延迟重建
→ 完整图负担过高，因此动态选择 LearningUnit
→ 自动选择可能优化错目标，因此用边界、上报与学习指标约束
```

迁移任务：假设你要学习一个陌生代码库。请说明如何保存代码证据、建立可修订参考、进行个人重建、处理分歧，并安排一次延迟迁移检查。最后指出一个你不会交给系统自动决定的高风险问题。
