# Roadmap

本文档记录当前实现相对于整体规划的覆盖情况，以及下一步开发的优先级判断。规则冲突时以 [consensus.md](consensus.md) 为准。

## 六引擎覆盖度

| 引擎 | 状态 | 说明 |
|---|---|---|
| Teaching Engine | 基本完成 | 分段揭示、五类针对性追问、反馈顺序、同节不重复出题、信心校准。这部分已超出最初设计。 |
| Knowledge Engine | 约 40% | `lesson-plan.json` 是**线性化的 MRG**，每节含 problem / solution / mechanism / concepts / depends_on，`source_refs` 带五类 support_type。但它是链不是图：概念无独立节点身份、关系无类型、跨节同名概念不合并。`source_manifest` 的 path + SHA-256 是真正的 SEL 原语，但只到文件粒度，未切分到 SourceUnit。 |
| Assessment Engine | 约 50% | 六维诊断、四种 verdict、隐藏 criteria 都在协议中，但落盘时 verdict 被压成一维，`criteria_met` 从未持久化——诊断做了，证据没留下。 |
| Learner Model | 最大缺口 | `attempts[]` 只写不读（唯一读取是单节课内的 resume 变式检索）。无跨课状态、无概念级掌握度、无遗忘曲线。 |
| Curriculum / Policy | 几乎没有 | 顺序在 build 时由 `depends_on` 固定。"下一个 8 分钟最值得做什么"这个核心问题目前无法回答。 |
| Memory Engine | 缺失 | mastered 即永别，无复习调度。 |

## 最关键的缺口：LRG 作为结构不存在

学习者的重建目前是 `attempts[].response` 里的一段自由文本。双图比较发生在模型推理过程中，产出一段反馈散文，然后比较结果就丢了。

也就是说，项目里最有原创性的机制——双图差异同时承担诊断、质检、忠实度验证、学习决策四重功能——**在实现中一次都没有真正运行过**。

其他缺口都是"少做了"，这一个是"核心假设仍未被检验"。

## 下一步优先级

### P0 — 让双轨机制第一次跑起来

保留插件形态继续教学（这部分在工作，不动它），只加两个本地脚本。

**1. 跨课学习者状态**
新增以**概念**为键而非以小节为键的 `learner-state.json`，跨课程累积：每个概念的最后一次证据、证据等级（即时／延迟／迁移）、信心与正确性是否背离。这一个文件同时解锁 Memory Engine 和复习队列，是性价比最高的改动。

**2. 结构化 LRG 捕获与比较器**
在主问题作答后追加一步：请学习者列出本节涉及的概念和它们之间的关系（三到五条），存成 node / edge 的 JSON。然后写一个 Comparator 脚本做概念对齐和关系比对，**输出差异清单而非单一分数**，差异分类为：

- 粒度不同
- 表述不同
- 关系方向错
- 缺失
- MRG 证据薄弱（这一类要能反过来质疑机器参考）

跑通这一步，才第一次拥有回答开放研究问题所需的数据。

**3. 落盘 `criteria_met`**
三行改动。不做纯属浪费已经完成的诊断。

### P1 — 形态扩展（在 P0 有数据之后）

**Claude Code / DeepSeek Harness 适配**：已完成（2026-08-31）——同一份技能目录通过 `.claude-plugin/` manifest 与 `~/.agents/skills/` 目录约定分别接入两个宿主，见 `plugin/README.md`。注意这只是"用得更顺"，架构天花板不变——仍无持久层、仍单课封闭，不解决"验证核心假设"。

**网页端 + 第三方模型 API**：能一次性解锁持久化、复习调度、图谱可视化、多设备。代价是自行承担鉴权、存储、密钥管理、成本控制，同时失去 skill 与子 agent 这套免费脚手架。一个容易被低估的成本：当前协议依赖强模型稳定遵循一份很长的文本约束，而第三方 API 的指令遵循能力差异极大——上多模型后，协议必须从"一段长提示"拆成显式的编排步骤。

**为什么 P0 在前**：共识文档末尾的十二个开放问题一个都没答。提示渐隐降低多少难度、单次活动的认知负担上限、Comparator 的机器偏向、双轨机制的收益能否覆盖交互成本——在这些还是问号时搭产品，等于把未验证的教学假设浇进混凝土。P0 跑通后：若双轨收益真的覆盖成本，数据里会看到，届时网页端有已验证的内核和已设计好的 schema 可直接搬；若收益不明显，只损失两个脚本，而不是一个产品。
