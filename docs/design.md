# Whetstone 设计核心

> 本文档是整个项目中心思想的最小完整表达。规范性约束的完整版本见 [consensus.md](consensus.md)（v2），冲突时以后者为准；理念阐述见 [learning-layers.md](learning-layers.md)；数据结构与协议工程定稿见 [specs/](specs/)。

## 1. 问题

传统阅读和普通 LLM 问答产生同一类失败：**看过很多，调用不出**。学习者积累了熟悉感，却没有形成可解释、可迁移的心智模型；LLM 能生成流畅解释，但缺少来源约束时，错误会被长期沉淀为"已学会的知识"；LLM 甚至能直接总结出一个对象的"本质"，但一旦展示，它就变成新的背诵材料。

项目要回答的不是"读到第几页"，而是：

> 学习者现在真正理解到了哪一层？哪些概念不稳固、哪些已经过期？下一次 8 分钟最值得做什么？

## 2. 立场

市面上的学习软件优化"无摩擦"，本项目站在相反一侧。学习科学的核心结论（desirable difficulties）是：让学习变流畅的手段大多损害长期保持，让检索变费力的手段大多增强它。因此：

- **不做摘要器**。"文件 → 摘要 → 闪卡"是立项时明确要避开的失败形态；
- **主动重建是核心学习行为**。学习者在隐藏参考的条件下，用自己的话解释概念、建立有类型有方向的关系——这是检索练习（g ≈ 0.5–0.6）与自我解释（g ≈ 0.55）的叠加，摩擦即机制；
- **高层理解不可传递，只能创造条件**。系统永不展示"为什么这样设计"和"背后的思想"，只通过顺序、问题和重复遇见让学习者自己到达那里；
- **学习效果优先于图谱完整和自动化程度**。图谱是工具不是目标。

## 3. 三层与四层

系统维护三种知识表示，其中机器参考图再分四个理解层：

```text
                原始材料
                    │
                    ▼
        原文证据层 SEL（材料说了什么）
        不可变来源单元 / 版本 / 定位
                    │
                    ▼
        机器参考图 MRG（有来源的正确框架）
        ┌─ 公开层：fact 事实 / mechanism 机制 ──▶ 讲义、概念笔记、学习者查询
        └─ 高层：rationale 理由 / principle 思想 ──▶ 只用于出题与评估，永不展示
                    │
                    ▼   隐藏参考，先重建
             学习者作答 ──▶ 抽取 + 单向诊断比较
                    │
                    ▼
        学习者重建日志 LRG（只追加；对学习者不可见不可编辑）
                    │
                    ▼
        概念注册表 + 带时效的学习者状态（跨课）
                    │
                    ▼
        变式题替代诊断 / 接缝问题 / 学科树可视化
```

- **SEL**：不可变、版本化的原文单元，一切来源定位的地基；
- **MRG**：在受信领域（经验证教材、经核实的 CS 知识）默认可信，可信按支持类型分级（`explicit > entailed > external > pedagogical_inference`）；它是诊断的尺子，但尺子的错来自抽取而非材料，所以来源定位不省；
- **LRG**：学习者摸索的全过程日志。不可编辑（否则退化为"改成正确答案"）、不可见（旧回答以去主体化的匿名命题用于复习）。

v1 设计中 MRG 与 LRG 对称、互相纠错。v2 把它改成非对称：MRG 是尺子，LRG 是被量的东西。这是范围决策而非研究结论——当前只面向受信材料；对 MRG 的质疑通道保留但低优先级。

## 4. 学习闭环

```text
选定可承受的局部子图（单次新概念 ≤ 4）
  → 阅读来源单元
  → 隐藏参考与全部高层，学习者预测 / 解释 / 建立关系，自评信心
  → 模型抽取概念、关系、命题与到达层次；对照 MRG 出差异清单
  → 追加 LRG 事件（原文、抽取、差异、判定；永不覆盖）
  → 针对性追问（一次一个，优先高信心错误），再答作为新事件
  → 延迟后以更少提示再次重建；在后续课程中以变式题、接缝题再遇
  → 脚本从日志派生跨课、带时效的学习者状态
```

四条贯穿性原则：

1. **提示渐隐**：全概念名 → 少数锚点 → 无提示 → 迁移情境 → 跨课接缝。脚手架必须随水平撤除；
2. **证据等级链**：即时识别 < 即时复述 < 延迟解释 < 延迟关系重建 < 新情境迁移 / 接缝。系统信任延迟与迁移证据，且"已掌握"必须带时效——过期即 `stale`；
3. **顺序即机制**：先重建再揭示；高层永不作为讲解出现。同一段"本质"，在学习者挣扎之后给是洞见，之前给是事实；
4. **记录层次而非只记对错**：每次作答记录到达的理解层（`fact / mechanism / rationale / principle`）；同一概念的作答链上层次如何爬升，是"理解在不在生长"的主要证据。第四层只记录不评分。

## 5. 关键约束

- **五类支持类型 × 四个理解层**贯穿所有知识输出。支持类型说证据从哪来，理解层说它是哪种知识，二者正交；
- **只追加**：LRG 不接受除追加之外的任何操作；MRG 修订产生新版本；
- **职责分离**：同一次无记录推理不得同时完成"生成、审核、改写、发布"。确定性检查交给脚本，语义判断交给模型，高影响歧义上报用户；
- **结构先于规则**：凡能用 schema、文件边界或校验器表达的约束，不写成提示词。高层"不得泄漏"靠分文件存放、渲染阶段不加载来保证，不靠规则；任一时刻加载给模型的有效规则集 ≤ 60 行；
- **允许不确定**："原文模糊""无证据""暂不判断"是合法状态；
- **多维状态**：掌握度不压缩为单一分数——回忆强度、解释质量、关系理解、到达层、信心校准、时效分开表示。唯一例外是可视化着色需要的标量，它不参与任何教学决策。

## 6. 跨课与可视化

- **概念注册表**：跨课程稳定的概念 id、别名、学科路径。对齐靠别名召回 + 模型语义确认 + 歧义时问学习者一句；禁止按名称或向量相似自动合并；
- **变式题替代诊断**：新课前置阶段对有记录且 `fresh / stale` 的概念，用一道变式检索题替代完整诊断——不跳过，使复用同时成为间隔复习；
- **接缝问题**：同一概念或思想在另一门课再现时，问"这是同一个设计思想吗，差在哪"。这是训练第四层理解的主要场合；跨课索引因此不只是效率工具；
- **可视化**：学科层级树为主视图（由学科路径派生），选中节点沿机制关系展开邻接。颜色深浅 = 当前掌握估计（证据等级 × 时效），长期未检索的概念自然变浅，图诚实显示遗忘；历史错误次数不进颜色。先用 Obsidian 目录 + graph 零成本实现。

## 7. 当前状态与边界

核心教学闭环已实现为跨宿主技能插件（见 [`plugin/`](../plugin/)，同一技能目录适配 Codex、Claude Code 与 DeepSeek Harness）并在日常自用：材料 → 问题链课程 → 逐节预测、重建、信心标注、针对性追问 → 延迟变式检索。

**v2 新设计尚未实现**：持久化知识库（MRG 导出、LRG 结构化记录、注册表、学习者状态、可视化导出）与协议阶段化都处于定稿待实现状态，见 [roadmap.md](roadmap.md)。

**明确不追求**：完全自治的多 Agent 网络、适用所有学科的唯一关系体系、多本书无差别合并、单一掌握分数、自动修订 MRG、让学习者查看或编辑 LRG、对第四层评分、自研遗忘模型、把学习者作答当免费标注劳动。

**开放问题**（不得当作已证明结论，完整清单见 consensus.md §17）：模型判定到达层的可靠性；去主体化复习是否保留 hypercorrection 效应；跨课别名召回的精度与确认负担；协议阶段化后的连贯性；**结构化 LRG 记录的交互成本是否可承受**——最后这条仍是项目的生死问题。
