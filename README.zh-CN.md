# Whetstone

> **学习软件都在承诺无摩擦，而摩擦恰恰是学习发生的地方。**

## 为什么叫 Whetstone（磨刀石）

Whetstone 的意思是磨刀石。选它做名字，是因为这个项目与市面上学习软件最本质的区别就藏在这个意象里。

主流学习产品的口号是"轻松学会"——它们把"学习的无感"当作卖点，优化的是流畅、顺滑、不费力。但学习科学过去几十年反复验证的结论恰恰相反：这类流畅感大多是**流畅性错觉**（fluency illusion），它让你觉得学会了，却不能在需要时调用；而那些让学习过程变得费力的策略——主动回忆（retrieval practice，元分析效应量 g ≈ 0.5–0.6）、自我解释（g ≈ 0.55）、延迟重建、间隔练习——才是形成长期、可迁移理解的策略。这在文献里叫 **desirable difficulties（必要难度）**。

刀不是靠泡在油里变锋利的，而是靠磨刀石的摩擦。磨的过程刀和石都在消耗，产出的是锋刃。这个项目的核心体验——读完材料后合上它，用自己的话重新解释每个概念、重建概念之间的关系、再用原文证据检验自己的重建——是艰难的。**这份艰难不是缺陷，而是机制本身。**

## 这是什么

Whetstone 是一个由 LLM 驱动的深度学习系统。它把你提供的书籍、文档或代码库转换成一条"问题 → 方案 → 新问题 → 下一方案"的可解释学习路径，然后要求你逐节完成主动重建：

- 读到方案之前先预测："你觉得该怎么解决？"
- 读完后合上材料，用自己的话解释概念和机制；
- 作答前自评信心，反馈优先曝光"高信心但错误"的地方；
- 追问针对你回答中实际暴露的最弱一点，而不是照抄题库；
- 下次继续时，先用一道变式题检验你上次的理解是否真的留存。

系统的反馈受原文证据约束：AI 生成的参考结构不是标准答案，你的重建与它冲突时，裁决依据是材料原文——任何一方都可能错。

## 项目状态

**研究原型。** 核心教学闭环（材料分析 → 问题链课程 → 逐节主动重建 → 证据约束反馈）已实现为 Codex 插件并在日常自用中。项目最有原创性的机制——机器参考图与学习者重建图的双轨比较——已完成设计但**尚未验证**。[共识文档](docs/consensus.md)末尾列出了十二个开放研究问题，它们不应被当作已证明的结论。

## 核心设计承诺

1. **不做摘要器。** "PDF → 摘要 → 闪卡"是本项目立项时就明确要避开的失败形态。LLM 的输出只是组件，受知识模型、学习者模型和学习策略约束。
2. **从记忆中重建是核心学习行为。** 学习者在隐藏参考的条件下解释概念、建立有类型有方向的关系。这是主动回忆与自我解释的叠加，并刻意避开了被 Karpicke & Blunt (2011) 证明低效的"照着书画概念图"。
3. **机器参考不等于真理。** AI 生成的结构是可审核的参考，不是答案。分歧回到原文证据裁决。
4. **重要结论必须可追溯。** 全程区分五类支持类型（`explicit / entailed / pedagogical_inference / external / unsupported`），教学推断不得伪装成作者原意。
5. **允许不确定。** "原文模糊""无证据""暂不判断"都是合法状态，系统不为图谱完整而伪造确定性。

## 快速开始

同一份技能目录适配三个宿主：

| 宿主 | 安装 | 调用 |
|---|---|---|
| Codex | 通过 `.codex-plugin/` 作为插件安装 | `$guided-learning-tutor` |
| Claude Code | `claude --plugin-dir ./plugin` | `/guided-learning-tutor:guided-learning-tutor` 或自然语言 |
| DeepSeek Harness | `cp -r plugin/skills/guided-learning-tutor ~/.agents/skills/` | `/guided-learning-tutor` |

```text
使用 guided-learning-tutor 技能学习这些材料：
- /path/to/document.md
- /path/to/repository

我希望学完后能够：解释核心设计，并把它应用到新问题。
```

详见 [`plugin/README.md`](plugin/README.md)。本地验证：

```bash
cd plugin && python3 -m unittest discover -s tests
```

纯标准库 Python，无第三方依赖。
